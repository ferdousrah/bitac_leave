# DataTable Action Buttons Fix - Summary

## Problem

After refactoring, **DataTable action buttons** (Edit, Delete, View buttons within data tables) were still using old file names and incorrect paths, causing 404 errors when clicked.

### Example Issues:
1. Click "সম্পাদনা" (Edit) button in User Groups table → 404 Error
2. Click "সম্পাদনা" (Edit) button in Users table → 404 Error
3. Click "View" button in Leave applications → 404 Error
4. Action buttons generated by server-side API endpoints had wrong paths

## Root Cause

DataTable action buttons are **generated server-side** in the fetch API files. During refactoring:
1. ✅ We moved view files to `views/` directories
2. ✅ We renamed files to kebab-case
3. ✅ We updated menu links and internal page links
4. ❌ **We forgot to update action button links in API files**

The API files are in `api/modulename/` but were generating links as if they were in the root directory.

## Understanding Relative Paths from API Files

API files are in: `api/modulename/fetch-file.php`

To reach different locations:

### To Views in Same Module
```php
// From api/users/fetch.php to views/users/edit.php
href="../../views/users/edit.php"
```

### To Root Files (Not Refactored Yet)
```php
// From api/users/fetch.php to manage_group_access.php (in root)
href="../../manage_group_access.php"
```

### To API Files in Other Modules
```php
// From api/leave/fetch.php to api/reports/leave-notice.php
href="../../api/reports/leave-notice.php"
```

### Path Breakdown
- `../` = Go up one directory level
- `../../` = Go up two directory levels (from api/modulename/ to root)
- Then navigate down to target location


Fixed all matches that needed relative paths.
